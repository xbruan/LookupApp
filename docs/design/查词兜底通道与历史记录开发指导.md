## 〇 一句话

让每一次查询都走到「**当前词典 → 借查别本 → 机器翻译**」这条链的尽头，
并把查词历史从「一个词」升级成「**一个词 + 它当时在哪本词典里**」。

D5 见 §二.5、D9 见 §五 §F。

**D1 的直接后果（明确写下来，别再犹豫）**：
「查不到 + 借词典 / 翻译按钮」那一页**不再是常态**，它变成**终态页** ——

## 二 现状（以本仓库的代码为据）

### 2.1 历史记录：**数据早就是「词条 + 词典」了，只有点击那一下没用它**

| 位置 | 现状 |
| --- | --- |
| 写一条历史（`native/src/engine/dsh_lookup_api.c` 的 `dsh_engine_lookup` 收尾处） | 三样都记 ✓：落点的**规范键名**（查 `apples` 落到 `apple`，历史写 `apple`）、词典 id、**入库当时的显示名快照** |
| 一条记录的形状（`native/src/store/dsh_history.h`） | `{word, dictId, dictTitle, at}` 字段齐 ✓ |
| 去重键 | **是 `(word, dictId)`**（`native/src/store/dsh_history.c` 的 `remove_same_key` / `dsh_hist_push`）→ 同一个词在两本词典里**本来就并存** ✓ |
| 渲染 | 显示词典名（`web/src/floating/main.ts` 的 `renderHistory`，`history-dict` 那一行）✓，而且是**按 `dictId` 现查名字**：改名后跟着变，查不到才退回历史里那份快照 ✓ |
| **点击** | **现在传 dictId 了**：`replayHistoryItem` 走 `lookup(word, { source: 'history', dictId: item.dictId })` ✓（参考实现那三版都漏了这一个参数，那正是这一项要修的真 bug） |

**当初的坏样子**：行上写着《新世纪汉英大词典》，点进去的词条却来自牛津高阶。
**而且宿主侧一个字都不用改** —— `dsh_engine_lookup` 早就接受第 2 个参数作**起点词典 id**
（传了就只在那一本里查、**不写当前词典**）。
→ **历史这一项是一处纯前端改动**（外加一处话术），这就是它能安全地只当一处 bug 修的原因。

**正确的做法仓库里本来就有**：返回栈一直传着它 —— `goBackLink` 压栈时带 `dictId`。

### 2.2 兜底那套机器：**已经收进内核**

决策在 `native/src/engine/dsh_fallback.c`（纯函数，从参考实现的 `src/Fallback/FallbackPlan.cs` 移植，
而那份参考实现**不随本仓库发布** —— 它整棵都不在本仓库；
执行在 `native/src/engine/dsh_lookup_api.c` 的驱动器里。B 级单测是 `native/tests/test_fallback.c`。

**接口**：`dsh_engine_lookup(engine, text, origin, dict_id?, out_json)`
（`abi/lookup.abi.json` 里那一条）。界面侧对应 `api.lookup(word, dictId?, origin?)`。
- 现有调用方（`api.lookup(word)` / `api.lookup(word, dictId)`）**一个字都不用改**；
- 只有 `origin ∈ {'input','selection'}` 才跑查词通道；`'link' | 'back' | 'history'` 一律不跑
  （检查标准就一条：`dsh_fallback_runs_channel`）。

### 2.3 「查不到」不是一张特殊页面

未命中那页就是**词条正文**：`native/src/engine/dsh_entry_api.c` 的 `build_notice` 生成
「未在《X》中找到“apple”。」，后面再补一排**可点的** `entry://` 候选链接（最多 6 条、排除查询词自己）。
所以查词通道改的**不是页面**，而是「谁来决定最终显示哪一份 `EntryPayload`」。
（这也是全程序里 `entry://` 链接唯一的来源。）

### 2.4 出路按钮是**事后补救**做的，这是必须改掉的结构

参考实现里的顺序是：`lookup()` → `applyPayload` → iframe 装好 → `refreshEntryChips()`
→ 只**算**出借查 / 翻译两条出路，再把按钮 `postMessage` 进词条正文。
若把自动兜底接在这一步，会得到：miss 页先画出来再被替换、`applyPayload` 调两次、
以及**递归调 `lookup()` 清空返回栈** → 选区那条路会把自己压的栈冲掉。

**现在的结构**：一条 `dsh_engine_lookup` 里把链**串完**，一次 IPC 只回最终那一份 `EntryPayload`，
`applyPayload` 只调一次；出路按钮**不再送进正文**（见 §三 C 与 §五 §A）。

### 2.5 已有的好东西（别重复造）

| 能力 | 位置 | 说明 |
| --- | --- | --- |
| 语种判定 | 内核 `dsh_language_decide(text, title, forced, null)`（`native/src/text/dsh_language.c`） | **发音与翻译共用同一处**；查词通道的字符类型判断必须复用它，**不许在 TS 里再写一份汉字范围**（否则就是「同一个东西两个来源」） |
| 主导字形 | 内核 `dsh_script_of` / `dsh_script_dominant`（同文件） | 决策表要的那一格 `script` **只许**由它填；`dsh_fallback.c` 里**一个汉字区间都不许出现** |
| 语种支持表 | 内核 `dsh_translate_language`（`native/src/translate/dsh_translate.c`）+ `dsh_language_name` | 不支持的语种**不许变成**别的语种，要如实说（那句人话由内核拼：「机器翻译暂不支持〈波斯语〉」，绝不退化成英语） |
| 翻译可用性 | `translate:status` → `{enabled, hasApiKey, targetMode, autoTranslate, …}` | 查词通道判「能不能翻译」就用它。⚠️ 老字段 `dictionaryFirst` **已删**，别再读 |
| 长文切分与批量 | **现实：内核一次只发一条文本，超长切分还没做**（`native/src/engine/dsh_translate_api.c` 顶上那段明写着「超长切分没做（服务端回 `45000130`）」；`native/src/translate/dsh_translate.h` 的 `DSH_MT_MAX_ITEMS` = 16 是 `text_list` 的条数上限） | ★ **与旧文档不一致**：参考实现那条「`SplitLongText` → 逐段查缓存 → `Batch`（≤16/请求）→ 按序拼回」在本仓库**没有对应实现**。D5 的「不设上限」照旧成立（它是产品决定），但「切分由现成逻辑做」这句话**现在不成立** |
| 译文缓存 | `native/src/engine/dsh_translate_api.c`：**进程内**、按内容寻址、`MT_CACHE_MAX` = 64 条、满了**从头覆盖（FIFO，不是 LRU）**；键是 `dsh_translate_cache_key(source, target, text)` | ★ **与旧文档不一致**：旧文档写「落盘 4000 条 LRU、跨重启有效」，实际**不落盘**。`shell/Lookup.App/AppPaths.cs` 里出现 `mtcache.json` 只是**从老目录搬家的白名单**（那个文件现在已经没有写入方）。所以 D10 的「回放走缓存」只保证**同一进程内不重复计费**（命中时 `cachedItems=1 / fetchedItems=0 / tokens=0`） |
| 借查探路 | 内核 `dsh_engine_probe`（打开 → 查一条 → 关掉，**不留常驻**）+ `dsh_engine_borrow` 的四态回话 | 查词通道第 3 步就用它。预算：自动那一次**总预算 300 ms**，`DSH_PROBE_BUDGET_MS` = 120 ms 是**单本**；「再问一遍」单本放大到 1500 ms、总预算 = 词长 × 1500 + 2000 |
| 词典 id 稳定性 | 内核 `dsh_dict_id_of_file`（`native/src/dict/dsh_dict_id.c`）= 对**整份 `.mdx` 的内容**算 SHA-256，分块读、常驻内存只多 64 KB | ★ **与旧文档不一致**：不是「全路径 SHA1 前 16 位」，而是**内容哈希** —— 于是**移动 / 改名文件不会让 `dictId` 失效**（换目录、重命名照样认得出来）；反过来**内容一变 id 就变**（换词典版本），旧历史会指向一本「不在词库里」的词典。详见 §五 §F |

### 2.6 两个必须一起处理的「既成事实」

1. **参考实现里有一段规范级注释**：
   > ⚠️ **不做"自动翻译所有查询"**：那里只有被显式调用才翻译，没有任何一条"查词顺带翻译"的路径。
   D1 与它**直接冲突**。那段注释必须改写（它是依据文档，不改就会变成"规范说不行、代码在干"）。
   本仓库这一侧已经没有那种说法：查词通道的第三步就是**自动翻译**，由 `translate.autoTranslate`
   控制；隐私靠**总开关默认关** + 翻译页那句**静态**隐私提示来守。
2. **`dictionaryFirst` 是一个"勾了没用"的开关**（参考实现里默认 `true`）：
   那边翻译页有勾选框、`translate:status` 也带着它，但**悬浮窗一处都没读**。
   它的字面承诺是「词典命中时不再显示翻译」—— 而那是出路按钮现在的固有行为（只在 `!entry.found` 时给）。
   → **D13：取消它**（连字段一起删）。它现在的"作用"只是让人以为自己关掉了某件事，属于误导性控件。
   本仓库的现状：界面上只有 `translateAuto`，`dictionaryFirst` **全仓库一处不剩**；
   而**老配置里残留的 `dictionaryFirst` 会被内核原样搬运、绝不是错误**（没建模的子键一律保留，
   见 §五 §A 最后一条）。

## 三 目标行为规格（这就是验收约定）

### A 决策函数的输入 / 输出（纯函数，唯一一份约定）

`native/src/engine/dsh_fallback.h` 的 `dsh_fallback_facts` / `dsh_fallback_result`
（字段与参考实现的 `FallbackFacts` / `Plan` 一一对应）：

```
dsh_fallback_facts {
  origin                 // 'input' | 'selection' | 'link' | 'back' | 'history'
  stage                  // 'start' | 'afterLookup' | 'afterProbe' | 'afterSuggest'
  script                 // 'han' | 'latin' | 'other'  ← 只许来自 dsh_script_of
  entry_found            // 起点那本查到了吗
  suggestion_count
  suggestion_has_exact   // ★ 那批候选里有没有一条精确命中
  hit_dict_id / hit_dict_title   // 别的词典里命中的那一本（空 = 都没命中）
  start_dict_title / started_from_current   // 这一趟的**起点**是哪一本、它是不是当前词典
  query                  // 用户选中 / 敲进去的那个词（选区那句提示要拿它数字数）
  hit_is_current         // 借查绕一圈问回当前词典（见下"借查绕回来"那条）
  unconfirmed[] / unconfirmed_count   // 没问完的词典名 ★与"没有"分开
  translate_enabled / auto_translate / translate_has_key / translate_supported
  translate_unsupported_message       // 不支持时那句如实的话，照抄
  entry_is_translation   // 这一页是不是译文伪词条（历史回放用）
  dictionary_missing / dictionary_file_gone / target_dict_title   // 不走通道那三条路的话术
  has_separator_dots / separator_retried
}
dsh_fallback_result {
  action                 // 'lookup' | 'show' | 'suggest' | 'probe' | 'translate'
                         // | 'terminal' | 'explain-error' | 'relookup'
  dict_id / stop / via / surface
  reason                 // 给界面写的解释行（"当前词典没有 · 已用《X》借查"）
  translate_why          // 终态页专用：「翻译为什么没用上」——四档分开说
  unconfirmed_note       // 终态页 / 结果页专用：「另有 N 本没能确认（《A》《B》）」
  unconfirmed_names[]    // 那几本的**名字**（原样带给界面）
  offer_translate / offer_recheck
  oom                    // 该有说明句却没拼出来 → 调用方必须**如实报错**
}
```

★ 比参考实现多出来的一格是 **`suggestion_has_exact`**：规格里「有候选 → 摆列表、停」那句话的
完整形状是五步，而参考实现那份表漏了「**先找精确命中，有就直接查它**」这一步。
漏掉的后果不是「少一条候选」，而是**输入框那条路永远出不来词条**：打一个确实存在的词按回车，
屏幕上永远只有一串候选、正文永远是空的。

`action` 里 **`relookup`**（去掉音节分隔点、用新词回起点再来一遍）也是这一版才有的，
理由见 §五 §C 最后那条。

### B 查词通道规格 · 输入框（`origin = 'input'`）

| # | 条件 | 动作 |
| --- | --- | --- |
| 1 | `script != han` 且当前词典有联想候选 | **摆候选列表，停**（既有行为，一个字不动） |
| 2 | `script == han` | **跳过当前词典的联想**（英文词典对中文词的前缀/编辑距离候选是噪音） |
| 3 | 当前词典查到 | 显示，结束 |
| 4 | 别本命中 | 用那本查并显示（**不切当前词典**） |
| 5 | 别本没问完 | 记 `unconfirmed`，**继续往下走**，但最终那一页必须带上「另有 N 本没能确认 + 再问一遍」 |
| 6 | 翻译可用（**四个条件全满足**：总开关开 · **自动开关开（D12）** · 有 Key · 语种支持） | 自动翻译，译文进正文框 |
| 7 | 否则 | **终态页**（见 §三 E） |

> 第 2 条就是用户原话里那个「含中文字符先看汉英词典」的落地形式：
> **不分类词典、不排除任何一本**，只改「联想这一档在不在当前词典发生」。

★ 还有一格位置很要紧：**带音节分隔点的词先问词典、不先联想**
（`pro·gress` 这种写法是**词典自己的排版**、不是用户打错的字 —— 拿它去拼前缀 / 编辑距离只会得到
一串噪音候选，还会把链**停在候选列表上**，于是"明明有 `progress` 却查不到"）。

### C 查词通道规格 · 选区（`origin = 'selection'`）

| # | 条件 | 动作 |
| --- | --- | --- |
| 1 | `dict:resolve` 有落点且 **≠ 当前词条** | 跳过去（**压栈** + 带 `scrollY`） |
| 2 | 落点 **= 当前词条** | 不跳，正文框底部一条提示，**结束（不进查词通道）** |
| 3 | 无落点 → 别本命中 | 用那本查（**压栈**：这是「在看词条时又查一个词」） |
| 4 | 别本没中 → 当前词典联想候选 > 0 | **不摆候选列表**（列表会顶掉正在读的正文）→ 正文框底部的提示里带**可点**的「你是不是想找：X / Y」 |
| 5 | 没候选 → 翻译可用（同 §三 B 第 6 条的四个条件） | 自动翻译（压栈，译文进正文框，返回能回到原来读到的位置） |
| 6 | 否则 | **正文框底部一条提示**（**不替换正文**） |

> ⚠️ 第 6 条那句提示里**不许无条件写「别的词典里也没有」**：
> `unconfirmed` 非空就说明有词典**没问完**（超时 / 出错），那时这句话是**替没被问过的对象下结论**
> —— 与"唯一不许让步的那条"（`unconfirmed` 非空必须带「另有 N 本没能确认 + 再问一遍」）直接冲突。
> 现在的约定：`unconfirmed` 非空 → 改说「另有 N 本没能确认（…）」并给一个**可点的「再问一遍」**；
> 为空才说「别的词典里也没有」。
> **落到界面上有两种形态，别搞混**：整页的结果页（借查命中 / 自动翻译 / 终态页）由内核的
> `annotate` 一处贴（它填 `unconfirmed_note` + `offer_recheck`），而且**那句话被并进整句 `reason`**
> —— 「另有 N 本没能确认（《A》《B》）」是产品约定、不是视图，所以由内核拼好、界面直接照抄；
> `unconfirmed[]` 仍然照给，因为 `#reader[data-unconfirmed]` 要的是**名字清单**、不是写给人看的那句话。
> 而**选区这条"不替换正文"的路**那句话也由内核拼（`selection_miss_phrase`），界面**原样显示、一个字都不拼**。
> ⚠️ **界面这一侧不许有第二处实现**：`main.ts` 里那个自己拼的 `unconfirmedNote()` 就是这个约束的反例 ——
> 文案的正确来源是内核（ADR-001 硬规则一第 2 条）。
> ★ **而且它现在有一个看得见的重影**：`#readerVia` 那一行是把 `reason` 与 `unconfirmedNote(payload)`
> 接在一起显示的，而 `reason` 里**已经含**这句话了 → 那句话说两遍。见 §十一 第 5 条。

> ⚠️ 第 4 条里「可点」这件事，约定如下（改这一段之前先读一遍）：
> · 提示条 `readerToast(message, tone, actions?)` 第三个参数就是那排出路按钮，点了按那个词**走选区那条路**
>   再查一次（`viaSelection: true`，一样到链的尽头）；没问完时那排按钮里多一个「再问一遍」；
> · **可点的提示不许自动消失**：`data-actions` 非空就不挂那个 1.8 秒定时器；
> · 容器 `.reader-toast` 仍是 `pointer-events: none`（**不许改** —— 它盖在词条上，要放行正文里的选区），
>   所以**只有按钮自己**开 `pointer-events: auto`（`web/styles/floating.css` 的 `.reader-toast-action`）；
>   少了这一条按钮"长得出来却点不动"；
> · 按钮**现造 DOM + `dataset.toastAction`**，点击走**事件委托**（按钮每次重建，逐个挂监听必漏）。
> 「祖先 `none`、后代 `auto` 到底点不点得动」是浏览器的**命中测试**行为，静态检查盯不到，
> 所以「候选**可点**」那一条只能在 D 级用真鼠标点一次、真跳、再退回（见 §八）。

> ⚠️ **★ 出路按钮由宿主页自己渲染（安全审查 F1 的修法，P1）**：
> 词条正文住在 `sandbox="allow-scripts"` 的**跨源 iframe** 里（`web/floating.html` 的 `#entryFrame`），
> 而**词典自带的脚本与桥接脚本跑在同一个 JS 环境**里 —— 中间没有可信边界。
> 所以按钮**长在正文里**的时候，词典脚本只要自己 `postMessage` 一条
> `{source:'lookup-entry', type:'chip', action:'translate', word:'它指定的文本'}`，
> 就能让宿主把**它挑的文本**发给收费的翻译接口：用户看到的是一次正常翻译，
> 账单和出去的字却都是词典决定的；换个词还能绕开按文本缓存。
> ★ **只加 `event.source` 校验挡不住**：发送方本来就是那个窗口 —— 来源校验能挡住"别的窗口冒充正文框"，
> **挡不住正文框里词典自带的脚本冒充桥接脚本**。
> 修法是**把授权还给可信父页面**：
> · 出路按钮由宿主页自己画 —— `web/src/floating/main.ts` 的 `renderEntryChips` + `#entryChips`
>   （`web/floating.html` 里那个紧随 `.reader-via` 的 `<div class="entry-chips" id="entryChips">`）；
> · 消息处理器里**不再有** `type === 'chip'` 这一支 —— 伪造的 chip 消息落进去**没有任何分支会接住它**
>   （`main.ts` 里处理器那一段的原话：「★ 这里**故意没有** `type === 'chip'` 这一支」）；
> · 正文框从此只上报**低权限事件**（滚动 / 高度 / 选区 / 空点击 / 播放自带音频 / `entry://` 跳转）；
> · **别用"给正文发一个令牌再收回来"替代它**：令牌和用它的人同处一个 JS 环境，词典脚本读得到，那等于没发；
>   也**别拿 `Event.isTrusted` 当用户点击的授权**。
> · 回归检查：A′ 级 `node tools/check-entry-auth.mjs`（它从**真实的** `main.ts` 里切源码跑，
>   不是照抄一份逻辑 —— 抄的那份永远不会红）。
> 顺带一处变化（有意为之）：按钮原来长在正文文档末尾，词条一长就得先滚到底才看得见；
> 现在它跟在解释行下面、不用滚，而且这一排**不占正文高度**，不会把词条挤掉一截。
>
> ⚠️ **正文文档里那套老机制还在，但已经是死代码**：词条文档里仍然有一个
> `<div class="lookup-chips" id="lookupChips">` 容器与它那段 `renderChips(items)`
> （参考实现的 `EntryDocument.cs` 产出的，已经生成进
> `native/src/dict/dsh_entry_doc.c` / `entry_assets.h`），**宿主不再往正文送 `chips`**，
> 所以它永远是个空容器。
> · **别改回 `#lookupChips`**，也别拿它当出路按钮的检查标准（出路按钮现在的检查标准是
>   `#reader[data-chips]` + `#entryChips`）；
> · 彻底拆掉它要动**参考实现**（不随本仓库发布）里的 `EntryDocument.cs` 并重新生成两份产物
>   （`entry_assets.h` 与 `tests/entry_doc_vectors.h`）—— 那是一次跨"冻结参考实现"的改动，
>   必须**单独做、单独验**，不许顺手带进来。

> ⚠️ **选区那条路的"起点"不等于"当前词典"**：
> 选区的第一站是**正文显示的那一本**（D7：正文属于哪本以载荷为准），
> 而那一本**可能是借查来的** —— 于是"起点"与"设置里的当前词典"在这条路上会分叉。
> 由此派生出两条硬约定，写"谁没有 / 用了谁 / 这一页属于哪本"时都必须先分清是在说哪一个：
> · **借查绕一圈问回当前词典时，不算借查**：那一页本来就是用户自己那本词典里的词条，
>   所以 `via = current`、**不带解释行**（写成「当前词典没有 · 已用《它》借查」是两处都说反了）；
> · **"谁没有"要点名起点那本**：起点是当前词典 → 「当前词典没有」；
>   起点是借查来的 → 「《那一本》里没有」。
> （内核侧由 `missed_phrase` 一处拼；B 级 `test_fallback.c` 与 D 级「机器翻译」那一组的
> "连续借查"都在盯它。）

> ⚠️ **音节分隔点要忽略，但只许"先原样问、问不到再去掉点问"**：
> 有些词典把词头显示成 `dic·tion·ar·y`，整条选中来查时那串点会跟着进查询 ——
> 词典里没有这个键，于是白白落到借查 / 机器翻译。
> 约定（顺序不能反）：① 先拿**原样**文本问起点那本；② 没问到且确实带分隔点 → 去掉点再问**同一本**；
> ③ 之后的借查探路 / 联想候选 / 翻译 / 终态页**全改用去掉点之后的写法**（驱动器里那个 `query`）。
> 只做第 ② 步不够 —— 用户在"当前词典真的没有、别本有"的情况下照样会失败。
> 在内核里这一步是**决策表的一条动作**（`relookup`）：只在「没命中 + 词里确实带点 + 还没试过」
> 三条同时成立时才发，执行完**回到起点再走一遍**（`separator_retried` 负责防来回重问）。
>
> **清单只有一处来源**：`abi/lookup.abi.json` 的 `constants.separators` 是唯一的定义处，
> 它生成给 C（`dsh_text_is_separator_dot` / `dsh_text_has_separator_dots` /
> `dsh_text_strip_separator_dots`，`native/src/text/dsh_textutil.c`）与 TS
> （`DSH_SEPARATOR_CODEPOINTS`，`web/src/shared/abi.ts`）。
> `web/src/floating/main.ts` 里那份 `SEPARATOR_DOT_CODES` **就是读生成的那一份**，不是手抄的
> —— 所以**不存在"两份清单漂移"这件事**了（参考实现里 C# 与 `main.ts` 各有一份，那个坑已消除）。
> ★ 但**认的字符比以前多**：现在共 **6 个码位** —— `·`(U+00B7)、`‧`(U+2027)、`・`(U+30FB)、
> 软连字符(U+00AD)、**`ˈ`(U+02C8 主重音)**、**`ˌ`(U+02CC 次重音)**。
> 后两个是**本版有意超出参考实现**的一处：词典把词头写成 `ˈæpl` 时它**永远不是词条名的一部分**，
> 而它只在"原样问不到"的第二遍里被去掉，所以不会误伤任何真实词条。
> **`-` `‐` `–` `—` 一律不认**（连字符是合法词条字符，删了会把 `well-known` 搞错），
> 生成脚本 `tools/gen-bindings.mjs` 里有一条检查标准专门盯着"清单里混进连字符"。
> 检查标准是**逐码点**比生成物与接口定义（`node tools/gen-bindings.mjs --check`）。
>
> ⚠️ **同一件事在「链接」那条路上要单独做一遍**：
> 上面那几步全发生在**兜底查词通道里**，而**词条里的 `entry://` 链接**是 `origin = 'link'` ——
> **不跑查词通道**（D11），查词通道里那一刀它一次都到不了。
> 所以词典把词头显示成 `dic·tion·ar·y`、它自己给的交叉引用 `href` 也照那个写法给的时候，
> 点这种链接只会得到"查不到"那一页。现在 `followEntryLink` 自己补同一刀：
> ① 先 `api.resolve(word)`（原样）；② `!landed && hasSeparatorDots(word)` 才去掉点重问；
> ③ 拿归一化后的 `target` 去 `lookup()`；词组链接的 `fallbackWord` 也一并归一化。
> 内核侧对应「不走通道的三条入口」在 `after_lookup` 那一档里也留着同一条 `relookup` 分支。
> ⚠️ **别去改 `resolve` 那条路**让它"自动去掉点再找"：那会让所有调用方（含历史 / 返回）
> 悄悄换语义；分工是"**只认出来 + 给出写法，决策在调用方**"。

### D 查词通道规格 · 历史 / 回退（`origin = 'history' | 'back'`）

| # | 条件 | 动作 |
| --- | --- | --- |
| 1 | 记录的那本在词库里 | 查它并显示（**不跑查词通道**） |
| 2 | 那本**不在**词库里 | 停。说清「《X》已不在词库中」+「重新导入到原路径即可恢复」（D8 / D9），**不跑查词通道** |
| 3 | 记录在、但文件丢了 | 另一句：「《X》的文件不在了」（与第 2 条**不是同一件事**，不许并成一句） |
| 4 | 记录的 `dictId` 是译文伪词典 | 回放翻译（D10，走缓存） |

> ⚠️ **这套话术对「返回」那条路同样成立**：
> 「返回上一层」那条路不能直接拿 `dict:lookup` 去撞 —— 撞上去得到的是两句**假话**
> （`null` → 界面弹「还没有可用的词库，请先添加词典文件」；
> 文件丢了那一档更糟：页面写「词库尚未加载完成，请稍候重试」，重试一万次也一样）。
> 两条路现在说**同两句话**，而且那两句话**由内核一处给出**
> （`native/src/engine/dsh_engine.c` 的 `dsh_dict_status`：`unavailable` = `removed` / `missing`，
> `note` = 整句人话），界面**原样显示**；
> 而且"那本已经不在词库"时名字从**返回栈**里取（词库里已经没有它了，别处问不到）。
> 检查标准两条：① 「不在词库」用**历史 / 返回栈里那份快照名**，「文件不在了」用**当前显示名**
> （改过名就该看到新名字）；② 两种情形**两句话**，不许合成一句。

### E 终态页（三档都没结果时的唯一出口）

必须同时说清四件事，缺一不可：
1. 当前《X》里没有；
2. 另外 N 本也**确定**没有（若 `unconfirmed` 非空 → 「另有 N 本**没能确认**」+ **可点的「再问一遍」**，
   **绝不许说"都没有"**）；
3. **翻译为什么没用上**：**四档分开说，别合并** ——
   ① 总开关关着（选项 → 翻译）② **「查不到时自动翻译」关着**（D12：这时候要给一个**可点的
   「翻译这个词」**，因为用户只是不让它自动，不是不要它）③ 没填 Key ④ 这个语种不支持
   （照内核那句如实说）；
   这四句由 `dsh_fallback_translate_why` 一处拼，界面一个字都不拼。
4. 保留拼写候选（`build_notice` 现在就在给）。

> 这一页是「每次查询都有结果」的**诚实版本**：`translate.enabled` 默认是**关**的，
> 而「总开关关着」与「自动开关关着」是**两件事**（D12）——
> 后者要用一条**可点的出路**接住（"翻译这个词"），不是一句解释就完。

> ★ **出路按钮到底给哪些**（`dsh_fallback_chips`，一条都别自己发挥）：
>
> | 档 | 给不给按钮 | 说明 |
> | --- | --- | --- |
> | **只有终态页** | 给（其余各页**一个都不给**） | 调用方按 `via == 'terminal'` 判 |
> | 「借词典查」 | **永不出现** | 已取消：借查已经是通道里的自动一步，不该再让用户点一下做同一件事（枚举值留着不动编号） |
> | 「再问一遍」 | 只在 `offer_recheck` 时给；**有词典没问完时**必须给 | 有它才敢说"别的词典里也没有" |
> | 「翻译这个词」 | 只在 `offer_translate` 时给（= 用户**自己**关掉了自动翻译） | 那是"他不让它自动"，不是"他不要" |
> | 总开关关 / 没 Key / 语种不支持 / 翻译失败 | **不给按钮** | 点了没用；理由由 `translate_why` 写清楚，该去改设置 |
>
> 按钮上那行字**也由内核拼**（`「再问一遍」` / `「还有 N 本没查完」` / `「翻译「word」」` 与悬停提示）——
> 文案是产品约定、不是视图。界面只画不拼。

## 四 架构选型：链条放在哪一层

### 4.1 结论：**链条在内核**（这一节的技术实质没变，结论按本仓库的现实更新）

本仓库有一条**硬规则**（`docs/adr/ADR-001-kernel-boundary-and-binding-generation.md` 硬规则一）：
**所有业务逻辑只存在于 C 内核，UI 严禁实现业务规则，UI 只是视图层。**
检查标准只有一句：**"这个决定，换个平台后还应该一样吗？"** —— 该一样的就是业务规则，必须在内核。

于是「链条放哪一层」这件事在本仓库**不是选型，是既定前提**：
决策函数已经在 `native/src/engine/dsh_fallback.c`（`dsh_fallback_decide`，纯函数），
执行在 `native/src/engine/dsh_lookup_api.c`；界面只负责把内核给的那几样画出来。

**下面这几条理由照旧成立，它们正是"必须这么分"的依据**：

| 理由 | 说明 |
| --- | --- |
| 判语种只有一个来源 | 语种/字形判定在内核（`dsh_script_of` / `dsh_language_decide`）。TS 侧若自己写汉字范围判断，就是第二个来源 —— 而**"什么算汉字"只许有一处** |
| 翻译的可用性 / 支持表 / 设置 / 凭据全在内核 | `dsh_translate_language`、`dsh_settings_translate`、`dsh_settings_volcengine_api_key`、`dsh_translate_plan`；界面一个字都不拼那句"为什么没翻译" |
| 借查探路同进程 | 直接走内核的探路/借查，`unconfirmed` 的语义**不会在 IPC 边界上被抹平** |
| **中间态在结构上不可能被画出来** | 一次 IPC 只回**最终**那一份 `EntryPayload` —— 用户要的「这一步不出现说明页」不靠自觉，靠结构 |
| **B 级可测** | 决策表是纯函数：表驱动跑一遍几毫秒，不打开词典、不联网 —— `native/tests/test_fallback.c`（入口 `wsl.exe -- bash tools/wsl-make-test.sh`）。而本仓库**没有**任何一套 TS 纯函数诊断基建（参考实现那几只诊断脚本一个都不在本仓库），所以"把判断留在没有廉价测试手段的那一侧"在这里根本不是一个可选项 |

**接口（最小改动）**：`dsh_engine_lookup(engine, text, origin, dict_id?, out_json)`。
- 现有调用方（`api.lookup(word)` / `api.lookup(word, dictId)`）**一个字都不用改**；
- **跑不跑查词通道只看 `origin` 这一条**（检查标准就是那一个函数 `dsh_fallback_runs_channel`）：
  `'input' | 'selection'` 跑，`'link' | 'back' | 'history'` 一律不跑；
- `dict_id` **只决定"从哪一本开始"**（起点那本，传了就只在那一本里查、**不写当前词典**），
  它**不影响**跑不跑通道。
  ⚠️ 旧文档写的"只有未指定 `dictId` 时才跑查词通道"**不是本仓库的行为** —— 以代码为准。

### 4.2 内核化之后**仍然成立**的代价与取舍（如实写下来，别假装没有）

1. **进度只能用事件**：一次查询是一条**请求/应答**，链要走"当前词典 → 借查别本 → 机器翻译（联网）"，
   长的时候好几秒，而请求回来之前界面拿不到任何中间态。所以阶段只能由内核/宿主**推**出来：
   `lookup:stage` 事件（`web/src/shared/types.ts` 的 `LookupStage`、`web/bridge.js` 的订阅、
   `main.ts` 那一处 `api.onLookupStage`）。
   **只说阶段与词典名**：`正在用《X》查…` / `正在查别的词典…` / `正在翻译…`。
   ★ **现状**：**接收端已就位、发送端还没有** —— 全仓库找不到一处 `lookup:stage` 的生产者
   （`shell/**` 里没有任何一处给它 `Emit` / `Broadcast`），所以运行期这几行字**其实看不到**。
   这是**还没落地**的一条，见 §十一 第 2 条。
2. **借查的执行搬进内核之后，断言的对象跟着变**：
   原先 A 级盯的是 TS 侧那几条（"借查走 `api.probe`、不许 `api.resolve`、不许按加载状态过滤"），
   内核化之后**它们会继续绿，而它们守的东西已经不在那儿了** —— 典型的"跟着错误一起绿"。
   所以这些检查标准必须**改成钉内核侧的新行为**：查词通道的触发条件、`origin` 白名单、
   `link` / `back` / `history` 不跑通道、`unconfirmed` 非空必带 recheck、终态页四档理由不许合并。
   **不能直接删**（删了就没防回归检查了）。
3. **D 级那两条降不下去**：见 §八 —— 它们要的是"选区点查词真的跳了、真的压了栈、
   返回回到原阅读位置"和"历史点选确实来自那一本"，这要跨进程 + 正文 iframe 归属，A/B/C 都判不了。
4. **UI 侧只剩"画"，但画的规矩更细了**：文案整句来自内核（`reason` / `translate_why` /
   `unconfirmed_note` / 按钮上的字），界面连"按钮上写什么"都不许拼；
   界面自己拼的只有 DOM 结构与类名。

> **备选（"链条留在 TS"）现在不成立**，两个理由都要记下来，免得以后有人重新提：
> ① 它直接违反 ADR-001 硬规则一；
> ② 那套「复杂的边界判断」会落在 TS 里，而**它在 TS 侧没有 B 级立足点** ——
> 要么新建一套 esbuild→Node 的 TS 纯函数诊断基建，要么只能靠 D 级几条断言碰运气。
> 用户的顾虑恰恰是「做成一个入口就会涉及复杂的边界判断」；把判断放在**没有廉价测试手段**的那一侧，
> 方向是反的。

**翻译页三行文案（照抄，别自由发挥）**：

| 位置 | 文案 |
| --- | --- |
| 开关行（`#translateAuto`） | **查不到时自动翻译** |
| 该开关的说明（`.speech-note`，**静态**：关着也看得见） | **词典里都没有的词，直接给出译文；关掉后只提示「查不到」，由你点翻译。** |
| 隐私提示 | **开启后，要翻译的文字会发给火山引擎（豆包）。词典里没有的词会自动翻译（可在下面关掉）。** |

> 说明文字**必须是静态的**，不许跟着开关状态变 —— 这是翻译页既有的约定
> （`web/manager.html` 那段注释：「关着的时候也得看得见，否则用户是在不知情下打开的」）。
> A 级有一条检查标准盯着它。

**凭证相关的界面约定（与 §四 的内核分工配套）**：
- **缺 Key 时三样控件（`translateEnabled` / `translateTarget` / `translateAuto`）置 `disabled`、
  但保留可见**（不是 `hidden`），原因写在 `title` 上，并给一个**永远可点**的「去『语音』页填写」跳转
  —— 解锁条件本身不许被禁掉，否则死锁。
- ⚠️ **改控件名必须连检查标准一起改**：这类检查标准很容易写成**带控件名**的形状
  （例如"某几个 `dom.translate*` 控件的某属性不许是 `hidden`"），只改 id 不改正则，
  它就会**不报错地**不再看守新控件（新的 id 里没有旧那个词根）。
- **老配置里残留的 `dictionaryFirst` 会被内核原样搬运、绝不是错误**：`translate` / `speech` /
  `volcengine` 三节里没建模的子键一律**原样保留、绝不丢**，所以取值时不必为它写迁移。

**DOM 界面标记（自动化靠它，不靠猜时长）**：

| 界面标记 | 意思 |
| --- | --- |
| `#reader[data-via]` | 这一页是从哪一步来的：`current` / `borrow` / `translate` / `terminal` |
| `#reader[data-unconfirmed]` | 没问完的词典名（逗号分隔）—— D4 的检查标准 |
| `#reader[data-chips]` | 算出来的出路**动作**（逗号分隔，例如 `recheck,translate`）；空串 = 一个都不给。**保留**，含义收窄为「**终态页的**出路」 |

> ⚠️ `data-chips` 这一笔**不能删**：它是出路按钮唯一的检查标准
> （按钮自己也在宿主页上了，但那是控件形状，不是"算出来的出路是什么"）。

### §B 执行纪律（都是踩过的坑）

1. **一次 `dsh_engine_lookup` 里串完，`applyPayload` 只调一次**。
2. **不许递归调 `lookup()`** 来实现借查那一跳 —— 会清空 `state.navStack`，选区那条路会丢掉自己压的栈。
3. **`viaBack` / `history` 必须显式关掉查词通道**（D11）：否则「退回一个查不到的词」又自动跳走，用户退不回去。
4. **在途作废**：`lookup()` 现在**没有**请求令牌（只有 `suggestToken` 管联想）。
   链变长（探路 + 翻译，可达数秒）之后，「等结果期间用户又查了一个词」会互相覆盖
   → **必须补一个 `lookupToken`**。这是**还没落地**的一条，见 §十一。
5. **阶段文案**：链期间必须能看出「正在用《X》查…」/「正在翻译…」，否则用户以为卡住。
   ★ 接收端（桥订阅 + 那个 toast）已就位，**生产者还没有** —— 见 §十一 第 2 条。
6. **不许报 token 数**：用户明确要求去掉，A 级有一条检查标准专门盯着（那句提示的代码里不许出现 `tokens`）
   —— 自动翻译更不许报。理由不是"少写几个字"：那个数字对用户没有可操作性
   （既不能凭它做决定，也没法拿它对账 —— 真正的用量在服务商后台），
   而**翻译成没成、用的是不是缓存**这两件事才是他要的。
7. **`unconfirmed` 非空时结果页必须带 recheck**（D4）。这是本方案**唯一不许让步**的一条
   —— 有它才敢说「别的词典里也没有」。

### §C 历史「词条 + 词典」

| 事项 | 做法 |
| --- | --- |
| 点历史里那一条 | `lookup(item.word, { source: 'history', dictId: item.dictId })`（**宿主不用动**，见 §2.1） |
| 点之前 | 先看本地那份词典清单：那本不在 → **不发起查词**，按 §三 D 第 2/3 条说话术 |
| 译文条目 | 由伪词典 id 分流：走翻译这条路回放（**不能**走 `dict:lookup`，见 §五 §E） |

**为什么这一项可以只当一处 bug 修**：它是**真 bug**（行上承诺 A、行为给 B），
改动是**一处点击 + 一处话术**、**零宿主改动**，而且能被 A 级与 D 级各一条盯住 ——
符合「只有真 bug 才修进参考实现的冻结版」。这也是 D6 的全部理由。

### §D `entryDictId` 收成具体词典

现状：它曾是 `null` 有两个意思（「这本就是当前词典」与「跟随当前词典」）。
压栈压的正是它 → **用户在管理窗换了当前词典之后，点返回会落到新的那本**。

改法（已落地）：压栈时用**载荷里那一本**（`payload.dictId`），
`state.entryDictId` 从此**永不为 null**（译文用伪词典 id）。
`applyPayload` 里那一段注释就是这条约定（原话：「别改回"null = 跟随当前词典"」）。
连带三处读它的地方一起看：`lookup()` 的取词典、`lookupFromSelection` 的落点判定、
`followEntryLink` 的落点判定 —— **判定与真跳必须问同一本**。

⚠️ 顺带一条：译文伪词典 id（`translate`）**不能拿去查词典**（词库里没有这一本，
拿去查只会得到一句误导的"还没有可用的词库"），所以凡"要拿去查"的场合一律先把它退回"当前词典"。

### §E 译文进历史 + 回放

- **写**：设计是**由内核在翻译成功之后写**，`dictId` = 译文伪词典 id，
  `dictTitle` **用内核给的那一份**（界面不许硬编码「机器翻译」——又是同一个东西两个来源的入口）。
  ★ **现状（与旧文档不一致，照这条写）**：内核现在只在**命中词条**时写历史
  （`dsh_engine_lookup` 收尾处：「只有 `landed != NULL` 才记」），译文那一半**还没有落点**。
  所以 D10 目前只落地了"怎么回放"这一半，见 §十一。
- **读**：历史条目 `dictId === 译文伪词典 id` → 走翻译这条路回放；**不能**走 `dict:lookup`
  （那本在词库里找不到 → 会掉进那句误导的"还没有可用的词库"）。
  界面这一半已落地：`replayHistoryItem` 一进来就按伪词典 id 分流，走 `renderTranslation`
  （它享受和真词条一样的待遇：朗读 / 复制 / 返回栈）。
- **回放的确定性（必须验）**：缓存键是 `(source, target, text)`
  （内核 `dsh_translate_cache_key`），而 `source` 由 `dsh_language_decide(text, title, …)` 现判，
  `title` 是**提示**。原次翻译时的提示来自「当时那一页的词典名」，回放时手上有的是伪词典名 ——
  **判定若漂移，缓存必失、可能重新计费、甚至换目标语种**。
  先按「不新增字段，回放如实报是否命中缓存」实现，并把这条写成断言；
  实测若漂移，再考虑往历史记录里加一个语种字段（**加字段要连设置规范化里重建历史那条路一起看**）。
- 回放**不压返回栈**（它是新一轮查询）。

### §F 词典被移除 / 文件丢失：现在是**内核给出的两句真话**

旧症状：拿去查时回 `null`，界面接住就说**「还没有可用的词库，请先添加词典文件」** ——
一句「你还没添加词典」出现在「你刚点的那本被移除了」的场合。根因是宿主侧对
「没有当前词典」与「id 不在词库里」**都回 null**。

按 D8 / D11，现在是**点之前**就查清、并且由内核一处给话：
`dsh_dict_status`（`native/src/engine/dsh_engine.c`）回 `unavailable`
（`""` / `removed` / `missing`）与 `note`（**界面原样显示**的那句人话）；历史每一行、词典清单
两处**同一套词、同一处实现**。三句话要能说清：
「《X》已不在词库中」/「《X》的文件不在了」/「重新导入到原路径即可恢复」。
**前端能做就不动协议**这条约定照旧：清单本身就在界面上（`state.dictionaries`），
所以"点之前先看一眼"这一步仍然是界面做的。

★ **D9 的技术前提在本仓库变了，必须照这条写**：词典 id 现在是**内容哈希**
（`native/src/dict/dsh_dict_id.c` 的 `dsh_dict_id_of_file` 对整份 `.mdx` 算 SHA-256），
**不是全路径哈希**。后果两条，方向相反：
- **移动文件 / 改文件名 / 换目录都不会让 `dictId` 失效** —— 内容一样就还是同一个 id，
  旧历史自动认得出来（所以「文件不在了」那种情况下，把文件放回去就行，**不一定要放在原路径**）；
- **文件内容一变（换词典版本）id 就变** —— 旧历史会指向一本「不在词库里」的词典，
  那时说的就是第 2 条那句话。

⚠️ 本仓库里**还有一处注释**按旧的"全路径哈希"写（`main.ts` 的 `replayHistoryItem` 里那句
「词典 id 是全路径的哈希：把文件放回原路径再导入一次」）。**以 `dsh_dict_id.c` 与自动生成的
绑定注释为准**（生成物里明写「id 是内容哈希，不是路径」）。改那一段之前先把这句话一起订正。

## 六 硬约定（跨文档与检查标准）

这一节收的是"不这么写就一定会有检查误报通过"的那些约定。**不含"改哪个文件的哪一行"**
—— 具体落点看 §五 §A 那张分工表。

1. **依据文档与代码必须一致。** 参考实现里那段「不做"自动翻译所有查询"」的规范级注释与 D1
   直接冲突，必须改写。本仓库这一侧的对应约定是：
   - 查词通道的第三步就是**自动翻译**，由 `translate.autoTranslate` 控制；
   - 隐私靠**总开关默认关**（`translate.enabled` 默认 false）+ 翻译页那句**静态**隐私提示来守，
     **不靠"永不自动"**；
   - 关掉自动翻译**不等于**不要翻译 —— 终态页必须给一条**可点的**「翻译这个词」。
   这条约定与 `docs/design/不带mdd的词典与机器翻译开发指导.md` 的 §B6 / §B8 是同一件事，
   两处要一起改、一起看。
2. **检查标准必须钉"新行为"，不能"跟着错误一起绿"。** 借查 / 翻译搬进内核之后，
   原先盯 TS 侧实现形状的那些断言**会继续绿，而它们守的东西已经不在那儿了**。
   它们必须改成钉这些事实：查词通道的触发条件、`origin` 白名单、
   `link` / `back` / `history` 不跑通道、`unconfirmed` 非空必带 recheck。
   **禁止直接删**（删了就没防回归检查了）。
3. **检查标准里写过控件名时，改控件名必须连检查标准一起改。** 这类检查标准很容易写成
   **带控件名**的形状（"某几个 id 的某属性不许是 `hidden`"那种）；只改 id 不改正则，
   它就会**不报错地**不再看守新控件（新的 id 里没有旧那个词根）。
   这条对**将来才补的**「缺 Key 时置灰」那条检查标准同样成立 —— 写它的时候就别把 id 词根写死。
   同理，`data-chips` 那一笔不许删（它是出路按钮唯一的检查标准）。
4. **删掉的东西不许回来**：`translate.dictionaryFirst`（「词典优先」勾选框 + 字段）已删，
   不许再加回那种"勾了没作用"的误导性控件；用户真正要的是 `translate.autoTranslate`。
5. **`unconfirmed` 非空时必须给「再问一遍」**，而**「没问完」绝不许并成「没有」**
   —— 这是本方案唯一不许让步的一条。
6. **过期的文档与注释跟功能一起改。** 换掉一个功能行为之后，描述它的文档必须同步
   （最容易烂在"被整条替换"的功能上）：翻译不再"只在用户点一下才发生"、
   `dictionaryFirst` 不再是设置项、链不再在界面里。本仓库里现在还能找到按旧说法写的注释
   （例如 `web/src/floating/main.ts` 的 `replayHistoryItem` 里那句"词典 id 是全路径的哈希"），
   发现一处订正一处。
7. **历史那一项的改动面要一直保持这么小**：它之所以能安全地修进参考实现的冻结版，
   靠的就是"一处点击 + 一处话术 + 零宿主改动"。以后往这条路上加东西要重新评估这个前提。

## 七 明确不做（写下来免得以后反复讨论）

1. **不做「别本的联想」**（D3）：别本只用探路回答「有没有、落在哪条」，命中就跳。
   要做它需要新开一个 probe 式 suggest，并记住「这批候选是哪一本算的、点了去那本查」
   （联想状态得扩成「照哪段文字 + 哪一本」）—— 是独立一轮的量。
2. **不按字符类型排除任何词典**（中文词**照旧**先问当前词典 —— 一次探路的代价，换来"不猜"）。
   真想要「中文优先问哪本」，以后让**用户指定一本"中文优先词典"**，别从 `.mdx` 头的
   Title/Description 里猜（那里没有「词典方向」字段）。
3. **不给自动翻译加长度上限**（D5）：豆包 MT 本身有硬上限
   （单条 1024 tokens、`text_list` 一次 ≤16 条），**不设长度上限**这个产品决定照旧；
   但 ★ **切分现在没有实现**（内核一次只发一条文本，超了服务端回 `45000130`）——
   所以"很长的选区"实际会失败。要么补切分，要么把"很长的选区要多问一句"提前做掉（见 §十一）。
4. ~~不动 `translate.dictionaryFirst`~~ —— **已作废**：D13 决定**取消**它（勾选框 + 字段一起删）。
5. **链接跳转不跑查词通道**（`entry://` 是词典内部目标，换本或换译文都是错的）。
   但**分隔点那一刀要在链接那条路上单独做一遍**（见 §三 C）。
6. **不改 `test.mdx`**；**不给参考实现的冻结版加任何查词通道代码**（冻结版只拿 §2.1 那一处真 bug）。

## 八 验证方案（A / A′ / B / C / D 五级；入口全部是本仓库里真实存在的）

**★ 为什么那两条降不到 A/B/C**：它们要判的是**窗口 / 阅读位置 / 返回栈**这类跨进程、跨文档的事实
——「节点上确实有那个属性」不等于「点下去真的跳了」，也不等于「跳回来时回到了原来读到的位置」。
把"选区点查词真的跳了、真的压了栈、返回回到原阅读位置"这条降级成静态断言，就等于
把对象从"真实的跳转"换成"看起来相关的替代指标"，**它会跟着错误一起绿**。

**新增测试项属于哪一级：先回答「这条需要启动真实程序吗？」** —— 不需要就**禁止**进完整测试
（完整测试的项数不应随功能增加而线性增长）。某次真往里加了，要说明"这几条为什么降不到 A/B/C"。

## 十 风险与回退

| 风险 | 触发时的表现 | 回退 |
| --- | --- | --- |
| 链条内核化之后某一档判断错 | 某个入口的 `via` / 出路按钮不对，而 A 级全绿 | **回退的粒度是一档、不是整条链**：决策与执行是分开的（纯表 + 驱动器），所以能单独把某一档动作改成"停"或把某一档的事实关掉，而**决策表与它的 B 级单测仍然有效**、不随实现改动而失效 |
| 用户抱怨"没点它自己翻" | 找不到地方关 | 两处必须都在，缺一处就等于关不掉：翻译页那个开关（D12）+ 终态页四档理由里的第 ② 档（关着时给一个**可点的"翻一下"**） |
| 中文输入在当前词典联想出噪音 | 输入中文回车后停在垃圾候选列表 | §三 B 第 2 条就是为它写的；C 级定向观察专门盯这一条 |
| 回放译文反复计费 | 缓存里同一句没命中 | 缓存**只在进程内**、64 条 FIFO，**跨重启必失**：先如实说明，再决定是加语种字段、还是把缓存落盘、还是改成"只在缓存命中时才回放，否则提示重新翻译" |
| 选区自动翻译把阅读位置弄丢 | 点「查词」后正文变了且退不回去 | 译文压栈是现成能力；D 级那条断言专门盯"返回回到原阅读位置" |
| 很长的选区翻译失败 | 服务端回 `45000130` 载荷过大 | 补切分，或在界面上把"很长的选区"提前说清（§七 第 3 条 / §十一） |
