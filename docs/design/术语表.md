> **这份文件回答一件事：文档里那些词到底是什么意思。**
> 它是给**读文档的人**准备的，尤其是没有软件工程背景的读者。
>
> - **放这里的理由**：这是**跨版本仍然成立的知识**，与具体哪一份实现无关，所以放 `docs/design/`
>   （本仓库只有一份文档树，不再按版本逐份复制）。
> - **它不是"现状 / 待办 / 进度"文档**，也不进自动加载预算。

## 一、写 README 的五条用词规则（已定）

> 原话：「README 是给人看的……中文名词一定要采用计算机行业已形成的共识的术语，
> 没有中文翻译就用本来的英文名，然后在 README 正文开头加一个解释这些中英文名词的术语表……
> 尽量一词一义，一词多义的地方就改变用词。」

1. **中文名词只用计算机行业已有共识的说法**，不用本项目自己的翻译。
2. **没有共识中文名的，直接用英文原名**（gate / fixture / golden file / probe / arena / binding / host / bridge）。
3. **一个词只表示一个意思。** 一个词有两个意思的，改掉其中一个的用词（拆法见 §五）。
4. **每份 README 的正文开头，必须放一份"只列该份用到的词"的术语表。**
   —— 不抄别人的表：只列这份文件真正出现的词。
5. **README 里一个字都不许出现旧词 —— 连"（旧称 X）"这种注解也不行。**
   "旧词 → 新词"的对照**只放在本文件 §六**（本文件不是 README，所以不受这条限制）。
   —— 理由：注解形式等于把旧词又搬回了 README，读者该看不懂的还是看不懂。
   ⚠️ **例外只有一个**：文件名 / 路径 / 命令 / 代码标识符 / 引用原话里的旧词要**保留原样**
   （例如真实文件名 `docs/design/查词兜底通道与历史记录开发指导.md` 里带旧名「兜底通道」，
   但文件名与标题都不许改 —— 改了会与二十多处源码注释里的引用对不上），
   但旁边要用一句话说明那是什么。

## 二、中文术语

### 2.1 架构与代码

| 术语 | 一句话解释 | 在本项目里 |
| --- | --- | --- |
| **内核** | 用 C 语言写的核心程序库，业务逻辑都住在这里面 | `native/` |
| **宿主程序** | 承载界面、并把界面显示到屏幕上的那个真程序（`host`） | `shell/Lookup.App`，打包后叫 `LookupApp.exe` |
| **接口（API）** | 一组可以被别人调用的函数 | `abi/lookup.abi.json` 里那 49 个函数 |
| **接口定义** | 唯一手写的一份清单，写明内核有哪些函数、每个函数收什么参数、返回什么、常量是几（中文旧称「契约」，英文旧名 contract；现在统一叫「接口定义」，英文用 `abi`） | `abi/lookup.abi.json` |
| **绑定** | 让另一门语言能调用 C 函数的那层代码（`binding`） | C# 那边是 `[DllImport]` 声明（`shell/Lookup.Interop/DshLookup.g.cs`） |
| **自动生成的接口代码** | 由脚本从接口定义算出来的文件，**不许手改**（旧称"生成绑定"，文件头写着 `GENERATED — DO NOT EDIT`） | `tools/gen-bindings.mjs` 产出 4 份 |
| **通信桥** | 页面与宿主程序之间互相传消息的那一层；页面不能直接调用系统功能 | `web/bridge.js`（**不要写成"传消息的那条通道"**，免得与「查词通道」相混） |
| **句柄** | 内核发给宿主的一个编号，宿主只当它是编号、不许拆开看里面（`handle`） | `dsh_engine *` / `dsh_dict *` |
| **错误码** | 每个可能失败的函数返回的一个数字：`0` = 成功，负数 = 不同的失败原因 | `abi/lookup.abi.json` 的 `dsh_error` |
| **返回结果** | 函数把结果写进你给的那个变量里，而不是用返回值带出来 | 例如 `char **out_json` |
| **不变式** | 任何时候都必须成立的一条关系 | 例如"问落点与真去查，结果必然相同" |
| **参考实现** | 上一代那一版程序；如今只在"重新生成产物"时才用它 | 上一代的 C# 实现（已发布、已停止加功能；**不随本仓库发布**） |
| **平台适配层** | 只做"操作系统相关那一半"的代码：开窗、托盘、剪贴板、HTTP | `shell/Lookup.Host` |
| **原子写** | 先写一个临时文件，再改名覆盖 —— 避免断电时留下写了一半的文件 | `native/src/platform/dsh_file.c` |

### 2.2 检查与测试

| 术语 | 一句话解释 | 在本项目里 |
| --- | --- | --- |
| **检查标准** | 事先写死的条件，用来判一件事算不算通过（旧称"判据"） | 代码注释与测试里都在用 |
| **实测结果** | 程序或测试真的打印出来的数字，不是估的（旧称"读数"） | 例：`共 2254 项，失败 0` |
| **约定** | 定下来的做法或说法，后来的人照着做（旧称"口径"） | 例："项目级文档一律放 `docs/`" |
| **断言** | 测试里那句"我认为结果应该是 X"；不成立就报错（`assertion`） | `native/tests/test_*.c` 里每一行 |
| **完整测试** | 把整套端到端测试跑一遍（旧称"全量"） | 参考实现（**不在本仓库**）：`smoke-test.mjs`；本仓库：`tools/test-shell-app.ps1` |
| **只跑一部分** | 只跑筛出来的那几组测试（旧称"切片"） | 例：内核里只编只跑某一个单测（`make build/bin/test_mdx`） |
| **测试分级** | 按"这条测试需要什么才能判"分级，能降级的就不许用最贵那层 | 本仓库是 **A / A′ / B / C / D** 五级 |
| **诊断脚本** | 只查看程序当前状态、不下结论的小脚本（`probe`） | `tools/probe-page.mjs` 等 |
| **标准答案文件** | 与参考实现逐字节比对的"标准答案"（`golden file`） | `tools/golden/baseline/golden-baseline.json`（冻结基线；来源记录在同目录 `provenance.md`） |
| **对照测试** | 把新实现和参考实现在同样输入下比结果，本项目要求逐字节相同（`differential test`） | `tools/golden-gate.ps1` |
| **防回归检查** | 专门盯着某个老问题、防止它再出现的检查 | 例："同一个进程里连开 5 次"那条（`tools/WindowsDllTest/Runner.cs`） |
| **存档** | 把检查的原始输出写进 `logs/` 留底（旧称"留档"） | `logs/` |
| **逐字节相同** | 两份文件的每一个字节都一样 | `web/bridge.js` 在本仓库与参考实现里逐字节相同 |

## 四、本项目自己起的名字（保留，但要解释）

> 这几个词是本项目在开发过程中形成的，**它们不是行业术语**，但在本项目里含义稳定，
> 因此保留原名，并要求每份用到的 README 都在术语表里解释一句。

| 名字 | 一句话解释 |
| --- | --- |
| **落点** | 这段文字在指定词典里**会落到哪条词条**（"apples" 的落点是 "apple"）。接口是 `dsh_engine_resolve`，返回的 JSON 字段叫 `landed` |
| **借查** | 在当前词典里没查到，就去**别的词典里查一次**；**不改"当前词典"**（与"切换词典"是两件事） |
| **查词通道** | 「当前词典 → 借查别的词典 → 机器翻译」这条自动往下走的链 |
| **终态页** | 查词通道全部试过、且翻译用不上时出现的那一页（不是"查不到"就立刻出现） |
| **出路** | 链走到尽头时给出的动作按钮（借查 / 翻译 / 再问一遍） |
| **探路** | 打开一本词典问一条就走、不把它留在内存里；单本预算 120 毫秒 |
| **不带 `.mdd` 的词典** | `.mdx` 旁边散放着样式表 / 字体 / 图片、**没有 `.mdd`** 的那类词典（旧词「散装词典」已废弃，见 §六） |
| **三层音源** | 发音的三条来源，按顺序试：词典自带录音 → 豆包在线语音 → 系统语音（离线） |
| **胶囊** | 屏幕边缘那枚胶囊形状的输入框（本程序的主界面） |
| **吸边** | 窗口贴到屏幕边缘时自动吸附上去 |
| **浮层** | 在正文里选中文字时，旁边浮出来的那排小按钮 |
| **拖拽把手** | 输入框上用来拖动窗口的那个区域 |
| **界面标记** | 界面上那些客观、可被程序读到的标记，专门用来做检查（旧称"记号"） |
| **词条正文** | 内核拼好的、可显示的那份词条内容（旧称"词条文档"） |
| **查词历史（词条 + 词典）** | 历史里记的不只是"查过哪个词"，还记"当时在哪本词典里查的" |

## 五、一个词两个意思的地方（已拆开）

| 原来的词 | 两个意思 | 现在怎么写 |
| --- | --- | --- |
| **通道** | ① 页面 ↔ 宿主程序的通信；② 查词自动往下走的链 | ① → **通信桥**（`web/bridge.js`）；② → **查词通道** |
| **门** | ① 参考实现的 `smoke-test.mjs`；② 本仓库的 A / A′ / B / C / D 分级检查；③ 指令预算那道检查 | ① → **完整测试**；② → **gate**；③ → **预算检查**（`tools/instruction-budget.mjs`） |
| **档** | ① 按词数分（≤4 个词 / ≥5 个词）；② 判定分两种；③ 两个入口（输入框 / 选区） | 分别写明"按词数分两种""两种判定""两个入口" |

### 9.4 批量替换的九条教训（拿七次真实事故换来的，别再犯）

1. **写入器必须显式指定行尾与 BOM** —— 别用会"顺手改格式"的默认值。
   `[System.IO.File]::WriteAllLines()` 在 Windows 上默认写 **CRLF**；`Set-Content` / `Out-File` 默认带 BOM。
   `.sh` 被加上 BOM 或 CRLF 之后 **`sh` 直接不认**（症状：`cd: $'tools/..\r'`、`line 1: ﻿#!/bin/sh`），
   **自动检查会因此根本跑不起来**（不是"红"，是"没跑"）。改文本就用**文本级 `Replace`**
   （`ReadAllText` → `Replace` → `WriteAllText`，行尾与 BOM 原样保留），不要拆成行数组再拼回去。
2. **改前先整树备份，改后拿它与现状逐文件对账。**
3. **结构计数不变式**：每个改动文件里 `{}()[]` 的出现次数必须与备份**逐一相同** ——
   它能一眼抓住"注释后面的代码被截断"这类静默事故（真发生过两处，其中一处丢了整条函数签名）。
4. **语法检查要"现版 vs 备份"两边跑**：`node --check`、PowerShell 解析器、`python3 -m py_compile`。
   只看现版通过不够 —— 要问"**是不是只有现版失败**"。
5. **"跳过比较行"的清单要写全**：不只是 `===` / `-match` / `includes`，还要包含 **`-replace` / `-eq` / `padEnd`**
   这类。有两次事故正是从这里漏过去的（D 级检查的词典标题数据被改、`.sh` 被写坏）。
   一句话：**凡是字符串被拿去比较、匹配、拼路径、当对象键的，一律不许改**。
6. **自证不可靠**：用与替换脚本同一套状态机写的审计，对它的 bug 只会一路绿灯。
   暴露问题的永远是**独立**的检查标准（与备份逐行 diff、结构计数、语法检查、真跑一遍自动检查）。
7. **归一化格式（行尾 / BOM）的那一遍，必须把「自动生成的文件」排除在外**，或者在它之后**重新生成一遍**。
   真实症状：`native/include/dsh_lookup.h` 被归一化顺手改动了 6 个字符，
   A 级检查随即报「与接口定义不同步」（`旧 22288 字符 / 新 22282 字符`）—— 重跑生成器即恢复。
   检查标准：**改完一定要跑 `node tools/gen-bindings.mjs --check`**，它是这类"被格式改写悄悄动过"的唯一照妖镜。
8. **"整串替换"的替换对，别写成会被展平的嵌套数组** —— PowerShell 里 `@(@('对拍','对照'))`
   （**只包一对**）会被展平成两个字符串，于是 `$p[0]` / `$p[1]` 取到的是**单个字符**，
   实际执行成了 `对`→`拍`、`听`→`完` 这种**单字替换**。真发生过（两个文件、21 处）。
   两条防法：① **多对一起写** `@(@(旧,新),@(旧,新))`（多对时只展平一层，恰好正确），
   要改一对就先包一层 `,@(...)`；② 动手前**先跑一次"命中 N 处"的试算**，看清楚替换对到底是什么再执行。
   这类事故**症状极隐蔽**：字数不变、语法没错、旧词黑名单也扫不出来。
9. **单字替换只有"等长改动检测"抓得住** —— 逐行比现状与备份，**只留长度相同、内容不同**的行；
   再把已知的等长合法改动（`口径`→`约定`、`回填`→`填回`、`词条文档`→`词条正文`）反向套回去；
   剩下的再筛**只差一个字符**的行。这一步的比对脚本在仓库外（用法：把"仓库根 + 备份根"交给它），
   本仓库里没有它。
